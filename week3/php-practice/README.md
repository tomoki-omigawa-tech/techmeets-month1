# コメント投稿フォーム（comment.php）

## 概要

PHP で作成したシンプルなコメント投稿フォームです。
フォームに名前とコメントを入力して投稿すると、入力内容をページに表示します。

---

## 見つけた問題点・修正した内容・学んだこと

### 問題1: ロジックエラー（代入演算子の誤用）

**問題のあったコード**

```php
if ($name = "") {
```

**修正後のコード**

```php
if ($name == "") {
```

**説明**

`=` は代入演算子であり、`$name` に空文字 `""` を代入してしまう。
代入式の値は `""` (falsy) になるため、条件が **常に偽** になり、名前が空でも
エラーメッセージが表示されないバグが発生していた。
比較には `==`（等値比較演算子）を使う必要がある。

---

### 問題2: XSS（クロスサイトスクリプティング）脆弱性

**問題のあったコード**

```php
echo "<p>" . $name . "さんのコメント:</p>";
echo "<p>" . $comment . "</p>";
```

**修正後のコード**

```php
echo "<p>" . htmlspecialchars($name, ENT_QUOTES, "UTF-8") . "さんのコメント:</p>";
echo "<p>" . htmlspecialchars($comment, ENT_QUOTES, "UTF-8") . "</p>";
```

**説明**

`$_POST` から取得した値をそのまま `echo` すると、悪意あるユーザーが
`<script>alert('XSS')</script>` のような入力を送信したとき、
スクリプトがブラウザ上で実行されてしまう（XSS攻撃）。

`htmlspecialchars()` を使うと、`<` → `&lt;`、`>` → `&gt;` のように
HTMLの特殊文字を無害な文字列に変換し、スクリプトの実行を防ぐことができる。

| オプション | 意味 |
|---|---|
| `ENT_QUOTES` | シングルクォートとダブルクォートの両方をエスケープ |
| `"UTF-8"` | 文字エンコーディングを明示してマルチバイト文字の誤処理を防ぐ |

---

## 学んだこと

1. **`=` と `==` の違い**  
   PHPに限らず多くの言語で `=` は代入、`==` は比較。条件式で `=` を使うと
   バグが生まれやすいため、常に意識して使い分ける必要がある。

2. **ユーザー入力は必ずエスケープして出力する**  
   フォームから送られたデータは信頼できない。画面に表示する直前に
   `htmlspecialchars()` を通すことで XSS を防ぐことができる。
   `ENT_QUOTES` と文字コード指定はセットで書くのがベストプラクティス。

3. **セキュリティは後付けでなく最初から組み込む**  
   今回のように小さなフォームでも脆弱性は発生する。
   ユーザーからの入力を扱う箇所は、設計の段階からエスケープ処理を意識する習慣が重要。
